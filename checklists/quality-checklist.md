# 公文质量检查清单

## 使用说明

本清单用于公文起草完成后进行质量检查，确保公文格式规范、内容完整、语言准确。请逐项核对，发现问题及时修改。

**检查顺序（三步，不可颠倒）**：

1. **先过「〇、钟主任九问」**——这是**定稿门槛**，考的是“这篇公文立不立得住”。九问不过，后面查得再细也是白查，直接回炉重写。
2. **再过「二、内容检查清单」**——按文种逐项核对要素是否齐备、依据是否充分、结尾是否规范。
3. **最后过「一、格式检查清单」「三、语言检查清单」「四、逻辑检查清单」「五、细节检查清单」**——技术性收尾。

> 制度类文件（制度／办法／规定／细则／操作规程／工作指引）：第 1、2 步照走，第 3 步改走「八、制度类文件专项检查」，并跳过公文特有的红头、发文字号、主送机关等项目。
> 时间紧、只做一轮检查时，优先做第 1 步（九问），再做「九、常规公文必查 20 项（速查表）」。

## 〇、钟主任九问（定稿门槛 · 必须九问全过）

> 来源：公文写作专家钟主任的九问审稿法。**这九问不是“检查项”，是“归零项”**——任何一问答不上来或答“否”，都说明这篇公文还没到可以送审的程度，须回炉修改后再答。

### 问1：第一句话是结论吗？三十秒内能抓住判断吗？

- **查什么**：正文第一段（不含“根据……”式依据引语）是否**先把结论／判断／请求摆出来**，而不是先铺陈背景、先讲过程、先绕圈子。
- **判据**：把首段单独拿给不了解背景的人看，30 秒内能否说出“这份文件要我干什么／它主张什么”。
- **反例**：`近年来，随着监管政策持续收紧，我公司业务规模不断扩大，人员编制相对紧张，现有工作模式面临诸多挑战……（三百字后）为此，拟请增加人员编制。`
- **正例**：`为满足业务规模扩大后的核算需要，拟请增加财务岗编制2名。现将有关情况报告如下：`
- **改法**：把结论句从文末／段末**提到最前**；背景、过程、数据一律后置到“情况说明”里。请示类尤其要“先说要什么，再说为什么”。

### 问2：每个小标题下面的内容，都能支撑它吗？

- **查什么**：**逐个小标题**问一遍——它下面那段，是不是真的在证明／展开**这个标题**？有没有“标题说的是A，内容写的是B”或“内容泛泛，换任何标题都套得上”。
- **判据**：小标题与正文之间，能不能用一句话说清“标题是判断，正文是论据”的支撑关系。
- **反例**：标题「二、风险防控扎实有效」，正文写的却是“上半年共召开各类会议12次”（与风险防控无关）。
- **正例**：标题「二、风险防控扎实有效」，正文写“代偿率由1.8%降至1.2%，三级资产占比升至92%，均优于监管要求”（标题是结论，正文是数据支撑）。
- **改法**：支撑不住的，要么**换标题**去贴合内容，要么**补内容**去支撑标题；两者都做不到的段落，删。

### 问3：信息分组了吗？同一组里是同一类事吗？

- **查什么**：全文信息是否**归了类**，有没有把不同性质的事塞进同一段／同一标题下（如把“人事”和“财务”混在一条里）。
- **判据**：同一标题下、同一段里的若干事项，能不能用一个**统一的分类词**概括（如都在讲“资金”、都在讲“人员”）。不能，就是没分组或分错了组。
- **反例**：一级标题「三、加强内部管理」，下面并列写着“完善议事规则”“压降融资成本”“规范档案管理”——三件事分别是治理、财务、行政，不同类。
- **正例**：一级标题「三、加强资金管理」，下面并列“压降融资成本”“优化债务结构”“提高闲置资金收益”——同为资金类，同类。
- **改法**：按“人、财、物、事、制”或按业务链条**重新归类**；归类后若某组只剩一条，考虑并入相邻组或删去。

### 问4：每组的排序逻辑说得出吗？全文有没有乱跳？

- **查什么**：各标题／各条之间的**先后顺序有理由**，且理由说得出口；全文读完没有“跳来跳去、前后颠倒”的感觉。
- **判据**：能否一句话讲出排序逻辑。常用且可辩护的排序：**按重要性**（重前轻后）、**按时间**（先发生先写）、**按流程**（先因后果、先做后评）、**按层级**（先总后分）。
- **反例**：第一部分讲“下一步打算”，第二部分讲“上半年成绩”（时间倒挂）；或“一、资金问题　二、人员问题　三、资金建议”（问题与建议交叉跳）。
- **正例**：`一、上半年主要工作　二、存在的主要问题　三、下一步工作打算`（时间顺序，符合“回顾—反思—展望”）。
- **改法**：给全文**定一个排序轴**（时间／重要性／流程），然后按轴把标题重排；凡是“讲事情”和“讲办法”混排的，一律拆成两段（先事后法）。

### 问5：删掉任何一句，会影响读者决策吗？

- **查什么**：**逐句**试删——删掉后，读者对“要不要批／要不要办／怎么办”的判断有没有变化。没有变化，这句就是冗余。
- **判据**：把全文压缩到“结论＋依据＋请求”三要素后，被删掉的那些句子，是否**一句都不影响决策**。
- **反例**：`在公司领导的高度重视下，在各部门的大力配合下，在全体员工的共同努力下，我们圆满完成了上半年的各项工作任务。`（删掉不影响任何决策）
- **正例**：`上半年担保余额由5.2亿元增至6.8亿元，同比增长30.8%。`（删掉后读者就不知道规模变化，影响判断）
- **改法**：套话、空话、表决心的话（“高度重视”“扎实有效”“再接再厉”）一律删；**数字、依据、时限**一律留。删到“再删一句就说不清事”为止。

### 问6：关键判断后面，跟着数字和论据吗？

- **查什么**：凡是**下了判断**（好／差、快／慢、充分／不足、达标／未达标）的地方，后面是否**紧跟可核验的数字或事实论据**。
- **判据**：每个形容词性的判断，能不能在**同一句或下一句**里找到支撑它的数据／事实。找不到，就是“空口下结论”。
- **反例**：`我公司风险防控工作成效显著，资产质量持续改善。`（“显著”“持续改善”无据）
- **正例**：`我公司风险防控成效显著：代偿率由1.8%降至1.2%，三级资产占比由85%升至92%，均优于监管要求。`
- **改法**：有据的**把数字补到判断后面**；没据的**把判断删掉**或降格为“基本”“总体”之类。

### 问7：各级标题连起来读，是一篇摘要吗？

- **查什么**：把**全文所有标题**（一级、二级）按顺序抄下来连读，是否自成一篇逻辑通顺、能独立看懂的**微型摘要**。
- **判据**：只读标题，不读正文，能否掌握全文骨架与主要判断；标题连读有无“前言不搭后语”“缺环”。
- **反例**：`一、基本情况　二、财务状况　三、有关建议`（读完不知道全文主张什么、建议什么）
- **正例**：`一、经营情况总体平稳　二、资金成本仍需压降　三、拟请核定新增授信额度`（标题即判断链条，连读即摘要）
- **改法**：把“表述性标题”（基本情况、有关事项）改成**判断性标题**（经营总体平稳、成本仍需压降）；标题之间补上“起承转合”的逻辑连接（问题→原因→举措）。

### 问8：请示写清了事项、依据和期望的批复了吗？

- **查什么**：**请示类必查**——① **事项**（请上级批什么，具体到可执行）；② **依据**（政策依据＋实际情况）；③ **期望的批复**（希望上级怎么批、批复后怎么办）。
- **判据**：上级读完，能不能**不用再问**就知道“要我批什么、依据是什么、批了我做什么”。
- **反例**：`关于有关工作的请示：现将有关情况报告如下……（通篇情况，结尾"妥否，请批示"）`——没说是请批什么。
- **正例**：`拟请同意我公司2026年度新增担保业务额度10亿元（事项）。依据《XX管理办法》第十条及2025年业务增长30%的实际需要（依据）。额度核定后，我公司将按季度上报使用情况（批复后安排）。妥否，请批示。`
- **改法**：请示正文**按“事项—依据—预期”三段式**重排；非请示文种（通知、报告、函）跳过本问，但须确认该文种的**核心要素**同等齐备。

### 问9：篇幅——还能再压三分之一吗？

- **查什么**：**全篇通读后强制自问**——能否在不丢任何有效信息的前提下，把篇幅压缩三分之一。
- **判据**：压掉三分之一后，结论、依据、数据、请求是否**一个不少**。若压完仍然完整，说明原稿有三分之一是水。
- **改法**（按收益从大到小）：
  1. 删套话、空话、表决心话（见问5）；
  2. 长句拆短、修饰词（“进一步”“切实”“扎实”“有效”“全面”）一律删；
  3. 重复表述合并（同一意思出现两次，只留一次）；
  4. 过程性描述压缩为一句（“经过反复研究、多次沟通、充分论证后”→“经研究”）；
  5. 数据只留支撑判断的关键项，过程数据、流水账删。
- **自检口径**：改完后统计正文字数，与改前对比，**下降幅度 ≥ 20%** 视为达标；不足 20% 的，说明还没压到位。

## 一、格式检查清单

### 1. 用纸及版面检查

- [ ] **用纸规格**：是否使用A4型纸（210mm×297mm）
- [ ] **纸张质量**：是否使用60-80g/m²胶版印刷纸或复印纸
- [ ] **装订方式**：是否采用左侧装订，不掉页
- [ ] **天头尺寸**：上白边是否为37mm±1mm
- [ ] **订口尺寸**：左白边是否为28mm±1mm
- [ ] **版心尺寸**：是否为156mm×225mm
- [ ] **印刷方式**：是否双面印刷
- [ ] **页码位置**：版心下边缘，左右各一字线

### 2. 字体字号检查

- [ ] **发文机关标志**：是否使用小标宋体（颜色红色）
- [ ] **文件标题**：2号小标宋体，居中排布
- [ ] **正文**：3号仿宋_GB2312字体
- [ ] **正文对齐**：正文及全部层次标题是否**两端对齐**（`w:jc=both`），不得左对齐
- [ ] **第一层次标题**：3号黑体（一、）
- [ ] **第二层次标题**：3号楷体_GB2312（（一））
- [ ] **第三层次标题**：3号仿宋_GB2312（1.）
- [ ] **第四层次标题**：3号仿宋_GB2312（（1））
- [ ] **发文字号**：3号仿宋_GB2312，六角括号〔〕
- [ ] **附件说明**：3号仿宋_GB2312（随正文），正文下空一行、左空二字编排，名称后不加标点
- [ ] **附件标识**：附件另面编排时，版心左上角第一行顶格编排的“附件”二字及附件顺序号，用3号黑体
- [ ] **附注**：3号仿宋_GB2312，加圆括号
- [ ] **抄送机关**：4号仿宋_GB2312
- [ ] **印发机关和日期**：4号仿宋_GB2312
- [ ] **页码**：4号半角宋体

### 3. 结构层次检查

- [ ] **第一层**：是否使用“一、”，黑体
- [ ] **第二层**：是否使用“（一）”，楷体_GB2312
- [ ] **第三层**：是否使用“1.”，仿宋_GB2312
- [ ] **第四层**：是否使用“（1）”，仿宋_GB2312
- [ ] **层次顺序**：是否严格按照“一、（一）1.（1）”顺序
- [ ] **标题回行**：是否为梯形或菱形

### 4. 成文日期检查

- [ ] **格式**：阿拉伯数字全称（如：2025年1月26日）
- [ ] **位置**：发文机关署名下方
- [ ] **月日格式**：不编虚位（如：1月5日，不写01月05日）
- [ ] **右空**：是否右空四字编排

### 5. 发文字号检查

- [ ] **格式**：机关代字+六角括号〔〕+年份+序号+号
- [ ] **年份**：是否4位阿拉伯数字全称
- [ ] **括号**：是否使用六角括号〔〕，不是[]或【】
- [ ] **序号**：是否不加“第”字，不编虚位（如：5号，不写05号）
- [ ] **位置**：发文机关标志下空二行，居中

### 6. 格式要素完整性检查

- [ ] **份号**：如需标注，是否6位3号阿拉伯数字
- [ ] **密级**：如需标注，是否使用3号黑体
- [ ] **紧急程度**：如需标注，是否使用3号黑体
- [ ] **发文机关标志**：是否居中
- [ ] **签发人**：上行文是否标注，格式是否正确
- [ ] **标题**：是否完整、居中
- [ ] **主送机关**：是否顶格，后有冒号
- [ ] **附件说明**：是否在正文下空一行
- [ ] **发文机关署名**：是否正确
- [ ] **附注**：是否加圆括号，在成文日期下一行
- [ ] **附件**：是否另面编排，在版记之前
- [ ] **版记**：首条分隔线在第一个要素之上
- [ ] **页码**：是否连续编排

### 7. 排版后 XML 技术核查（本地 docx，python-docx／手工写 XML 时必查）

> **API 返回成功 ≠ Word 里正确**。以下各项须打开成品 zip 逐项统计，只看脚本返回值即为**假过**。
> 一键校验：`python @scripts/verify_docx.py <成品.docx> --type gongwen|zhidu`（详见 `@SKILL.md`「XML 七查」）

- [ ] **主题字体零残留**：全包 `asciiTheme` / `eastAsiaTheme` / `hAnsiTheme` / `cstheme` 计数 = 0（主题字体优先级高于显式字体名，残留则实际渲染跳字体，最易假过）
- [ ] **主题色零残留**：全包 `themeColor` / `themeShade` / `themeTint` / `themeFill*` 计数 = 0；段落与字符样式的 `<w:color>` 统一为 `000000`
- [ ] **自动间距与固定间距均已清零**：`Autospacing` 计数 = 0；且 `<w:before w:w="非0"/>`、`<w:after w:w="非0"/>`、`<w:spacing … w:before="非0"`、`<w:spacing … w:after="非0"` 计数均为 0。**须用 `[1-9]\d*` 逐属性统计**，不可用 `\d+`，否则同一标签只匹配首个属性，“清洗漏一个、校验也看不见”，双双假过
- [ ] **段落装饰边框**：正文段落 `<w:pBdr>` 计数 = 0（`header*.xml`、`styles.xml` 中的另行判定）
- [ ] **引号全角**：正文半角直引号计数 = 0，中文全角引号数量 > 0（代码块内的 XML 属性引号豁免）
- [ ] **页边距合规**：必须从 `<w:pgMar>` 的**属性**读取（不得读 `sectPr` 直子）。公文 上37/下35/左28/右26mm（2098/1984/1588/1474 twips）；制度 上36/下36/左27/右27mm（2041/2041/1531/1531 twips）；页面 A4（11906×16838）
- [ ] **正文两端对齐**：`<w:jc w:val="left"/>` 计数 = 0（正文及层次标题应为 `both`）
- [ ] **层次标题首行缩进**：第一至第四层次标题段落均含 `w:ind w:firstLineChars="200"`（首行缩进2字符），与正文一致；仅文件标题、发文机关标志（居中）、主送机关（顶格）不得带首行缩进
- [ ] **pPr 子元素顺序**：`pStyle→keepNext→keepLines→pBdr→shd→spacing→ind→contextualSpacing→jc→outlineLvl→rPr→sectPr`（顺序错则 Word 静默忽略该属性）
- [ ] **szCs 与 sz 同值**：避免中英混排字号跳变
- [ ] **Title 样式已净化**：无 `w:spacing`（字符间距）、无 `w:kern`、无 `w:pBdr` 下边框、无 `w:contextualSpacing`
- [ ] **逐段样式映射正确**：打印每段的 pStyle 与前 38 字，确认标题／正文／主送／落款各归其位，无错挂
- [ ] **字体真实可用**：枚举 `%WINDIR%\Fonts` 与 `%LOCALAPPDATA%\Microsoft\Windows\Fonts`，核对方正小标宋简体、黑体、楷体_GB2312、仿宋_GB2312 是否已安装；缺失时**不得降级替换**，须保留规范字体名并向用户明示
- [ ] **表格单元格无裸 run**：写入单元格不得用 `cell.text = ""` 清空（会留下无 `w:rPr` 的裸 run，字体不受控）；应先移除原有 run，再 `add_run` 并显式设字体。裸 run 计数 = 0
- [ ] **表格列宽等于版心**：定宽（fixed）布局下各列宽之和须等于 8844 twips（版心 156mm），`tblGrid` 与每个 `tc` 双重写入，既不满溢也不收缩
- [ ] **引文块体例统一**：案例、汇编、说明类文书中引用成文全文时，引文用 3 号楷体_GB2312、整体左缩进 2 字符（`w:leftChars="200"`）、不设首行缩进，与正文（仿宋、首行缩进 2 字符）形成明确区分
- [ ] **页码页脚距离**：公文 `w:pgMar@w:footer` = 1588 twips（一字线距版心下边缘 7mm），非 Word 默认的 992
- [ ] **核查方式**：用 Python 读取 XML 逐字验证，不仅凭编辑器 API 返回值或“生成成功”判断（详见 `@SKILL.md`「本地 docx 排版实操铁律」）

## 二、内容检查清单

### 1. 标题检查

- [ ] **准确性**：是否准确概括内容主旨
- [ ] **完整性**：发文机关+事由+文种
- [ ] **规范性**：事由是否使用“关于”引出
